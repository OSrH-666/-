
# 大学生学生会管理系统 - 测试计划

## 1. 测试概述

### 1.1 项目背景

本系统是一个大学生学生会管理系统，旨在为学生会提供活动管理、社团管理、签到管理、用户管理等核心功能。系统支持三种角色：**管理员**、**社团负责人**、**学生**，每种角色拥有不同的权限和功能访问范围。

### 1.2 测试目标

- 验证系统各功能模块的正确性
- 确保系统稳定性和可靠性
- 验证三种角色的权限隔离和功能访问控制
- 发现潜在的bug和性能问题
- 保证系统符合需求规格说明
- 验证数据一致性和安全性

### 1.3 系统角色定义

| 角色 | 标识 | 权限描述 |
| :--- | :--- | :--- |
| 管理员 | ADMIN | 系统最高权限，可管理所有用户、社团、活动，进行审核操作 |
| 社团负责人 | CLUB_MANAGER | 可管理自己负责的社团及其活动，管理社团成员，审核报名 |
| 学生 | STUDENT | 可浏览活动、报名活动、签到、查看个人信息 |

### 1.4 测试范围

| 模块 | 功能 | 优先级 | 涉及角色 |
| :--- | :--- | :--- | :--- |
| 用户认证 | 登录、注册、密码修改、权限验证 | 高 | 所有角色 |
| 用户管理 | 用户列表、角色分配、状态管理 | 高 | 管理员 |
| 社团管理 | 社团创建、编辑、删除、查询、审核 | 高 | 管理员、社团负责人 |
| 活动管理 | 活动创建、编辑、删除、查询、发布、结束 | 高 | 管理员、社团负责人 |
| 社团成员管理 | 成员加入、退出、角色分配 | 中 | 管理员、社团负责人、学生 |
| 报名管理 | 活动报名、取消报名、报名审核 | 中 | 社团负责人、学生 |
| 签到管理 | 签到记录、统计、导出 | 中 | 社团负责人、学生 |
| 总结管理 | 总结提交、审核、查询 | 中 | 社团负责人、学生 |

## 3. 测试策略

### 3.1 测试类型

1. **单元测试**：对单个函数、方法进行测试
2. **集成测试**：测试模块间的接口和交互
3. **系统测试**：对整个系统进行测试
4. **接口测试**：测试API接口的正确性
5. **权限测试**：验证角色权限隔离
6. **回归测试**：Bug修复后的验证

### 3.2 测试方法

- **黑盒测试**：不考虑内部实现，只关注输入输出
- **白盒测试**：根据代码结构进行测试
- **边界值测试**：测试边界条件
- **等价类划分**：将输入划分为等价类进行测试
- **场景测试**：模拟真实业务场景

### 3.3 测试流程

1. 需求分析 → 2. 测试用例设计 → 3. 测试数据准备 → 4. 测试执行 → 5. 缺陷记录 → 6. 回归测试 → 7. 测试报告

## 7. 缺陷管理流程

### 7.1 缺陷分类

| 级别 | 描述 | 示例 |
| :--- | :--- | :--- |
| P0 | 致命缺陷，系统无法运行 | 登录失败 |
| P1 | 严重缺陷，核心功能不可用 | 活动无法创建 |
| P2 | 一般缺陷，功能部分可用 | 界面显示异常 |
| P3 | 轻微缺陷，不影响功能 | 文字拼写错误 |

### 7.2 缺陷记录格式

| 字段 | 说明 |
| :--- | :--- |
| Bug ID | 唯一标识 |
| 标题 | 简短描述问题 |
| 描述 | 详细描述问题复现步骤 |
| 截图 | 问题截图 |
| 级别 | 缺陷级别 |
| 模块 | 所属模块 |
| 状态 | 新建/待修复/已修复/已验证 |
| 发现人 | 测试工程师 |
